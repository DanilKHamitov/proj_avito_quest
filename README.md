# Поиск кандидатов (Retrieval) 

**Описание решения**

Для поиска кандидатов я использовал `cointegrated/rubert-tiny2`. Сначала попробовал запустить модель без дообучения - перевел тексты в эмбеддинги и искал через косинусное расстояние. Recall@50 получился около 40.5%. Базовый BERT плохо справляется со  сленгом и синонимами площадки, поэтому метрику разогнал через дообучение.

В качестве текстовых признаков я склеил `item_title_raw` и `item_description_raw`, так как чисто по коротким заголовкам модель часто не могла найти контекст.Также отдельно при подсчете косинусного расстояния добавлял бонус за нахождение в одной локации. Обучение построил на базе Contrastive Learning с лосс-функцией `MultipleNegativesRankingLoss`. В качестве позитивных пар использовал историю кликов: запрос пользователя и текст объявления, на которое он перешел. После дообучения на этих парах Recall@50 поднялся до ~73%.

**Основные проблемы и решения:**
1. **Нехватка памяти (OOM):** Attention тратил много памяти,пришлось фиксировать размер текста 64 токенами,используя pooling заполняя лишние нулями,нормализуя векторы, чтобы проще и быстрее считать косинусное расстояние. На инференсе батч поднял до 256, так как там не нужно считать градиенты,там все хорошо заработало.
2. **Семантический разрыв:** Базовая модель не связывала  сленг с формальными описаниями товаров.Проблему устранил дообучением,чтобы выучить зависимости конкретно под эту площадку.
3.  **Пропуски в данных** Были Nan в данных, что мешало склеивать информацию для подачи в трансформер,пришлось ее заменять на пропуск(пустую строчку).
